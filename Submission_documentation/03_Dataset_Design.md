## 2. Column Definitions

| Column | Type | Description | Requirement Mapping |
|---|---|---|---|
| case_id | String | Unique identifier e.g. NET-001 | Case evidence |
| symptom | String | User-reported failure in plain language | Symptom requirement |
| topology_note | String | Network topology, devices, addressing context | Topology note requirement |
| osi_layer | String | Primary OSI layer(s) responsible for the fault | OSI layer requirement |
| concept_tag | String | Network engineering domain (VLAN, OSPF, NAT, etc.) | Concept tag requirement |
| severity | String | High / Medium / Low | Severity classification |
| show_outputs | String | Captured Cisco IOS show command output (multi-line) | Show outputs requirement |
| expected_fault | String | Ground-truth root cause label | Expected fault requirement |

All 8 columns are present and non-empty across all 33 rows (verified).

## 5. Show Output Quality — Design Principles

Each show_outputs field was designed to be a realistic capture of what a Cisco IOS device
would actually display. The following principles were applied:

1. EXACT SYSLOG FORMAT: Error messages use the actual Cisco IOS syslog format
   e.g. %IP-4-DUPADDR, %CDP-4-NATIVE_VLAN_MISMATCH, %PM-4-ERR_DISABLE

2. REALISTIC COMMAND HEADERS: show command output includes the prompt and command echo
   e.g. "R1#show ip nat translations"

3. MINIMAL SUFFICIENT EVIDENCE: Only the relevant portion of output is included,
   as an engineer would capture from a terminal

4. DETERMINISTIC-COMPATIBLE: For NET-001 to NET-013, the exact string required by
   the corresponding checker rule is present in the show_outputs field

5. LLM-COMPATIBLE: For NET-014 to NET-033, the show output contains enough context
   for a network-knowledgeable LLM to reason about the fault, but no exact syslog
   match exists in the checker rule set

## 6. Dataset Generator

File: scripts/generate_cases.py (574 lines)

The generator contains all 33 cases as Python dicts and writes them to data/cases.csv.
To regenerate the dataset from scratch:

  python scripts/generate_cases.py

The CASES list in generate_cases.py is the authoritative source for the dataset.
The cases.csv file is the generated output used by the application at runtime.
